Algorithmic Foundation

Multinomial Naive Bayes & TF-IDF

Phishing attacks predominantly leverage high-entropy psychological triggers (urgency, panic, account restrictions, bait prizes). Multinomial Naive Bayes operates on the foundational principles of Bayes' Theorem to calculate the posterior probability of a message being malicious:

Bayes' Classification Theorem:
P(Phishing | Words) = [ P(Words | Phishing) × P(Phishing) ] / P(Words)
1. Sublinear TF-IDF Vectorization:

We calculate 1 + log(tf) multiplied by Inverse Document Frequency (IDF) to prevent very frequent words from skewing the model while capturing unigram and bigram token pairings (such as "account suspended", "verify identity").

2. Laplace Smoothing (α = 0.1):

Additive Laplace smoothing ensures that novel tokens never receive zero probability in the multinomial likelihood distribution, preventing false negative blind spots.

3. Stratified Evaluation:

Trained and evaluated on balanced corpora with zero-tolerance false negative optimization to prioritize user credential safety above all else.

NLP Feature Extraction

Why Naive Bayes for Cybersecurity?

While deep neural networks require gigabytes of VRAM and high inference latency, Naive Bayes provides:

  • Sub-Millisecond Inference: Processes thousands of incoming emails per second with minimal CPU and memory footprints.
  • 100% Explainability: Log-probabilities can be decomposed directly to show security analysts exactly which token triggered the threat alert.
  • Zero GPU Dependency: Easily deploys on Render's free tier without expensive hardware acceleration.
Production models in CyberShield AI feature dynamic token weight ratios to minimize corporate false positives.
URL Analysis Heuristics

RFC 3986 Heuristic Detection Vectors

Attackers exploit human perception and protocol nuances to disguise attack links. CyberShield inspects ten distinct structural threat patterns:

Naked IP Hostnames +40 Risk

URLs utilizing raw IPv4 or IPv6 addresses (e.g., http://185.220.101.5) bypass legitimate DNS registration records and domain reputation filters.

Brand Impersonation +45 Risk

Attackers insert trademarks like PayPal, Microsoft, or Apple into third-party apex domains (e.g. paypal-security-update.com).

URL Shortener Masking +25 Risk

Redirect services (bit.ly, tinyurl, t.co) conceal the true destination server from gateway scanners and human visual inspection.

Abused TLD Profiling +30 Risk

Disposable, free, or low-cost TLDs (.xyz, .top, .tk, .buzz, .club) exhibit disproportionately high malware hosting density.

Insecure Protocol (HTTP) +20 Risk

Authentication and account verification portals hosted over unencrypted HTTP expose credentials to man-in-the-middle sniffing.

Userinfo @ Obfuscation +35 Risk

The RFC userinfo delimiter (https://legit.com@evil.com) tricks victims into reading the prefix while the browser navigates to the host after the @.

Cybersecurity Defense SOP

SOC Playbook: Incident Mitigation Workflow

Standard Operating Procedures (SOP) when a high-risk or malicious threat vector is confirmed:

1 Phase 1: Containment
  • Isolate endpoint from local network if links were clicked or files downloaded.
  • Revoke all active sessions and rotate enterprise passwords if credentials were entered.
2 Phase 2: Technical Triage
  • Export raw RFC 822 email headers (.eml) to inspect originating IP and Return-Path.
  • Verify SPF, DKIM signature validity, and DMARC alignment status.
3 Phase 3: Hardening
  • Blacklist malicious FQDN and IP address on perimeter firewalls and secure web gateways.
  • Submit URL to Google Safe Browsing and PhishTank community feeds to protect other users.
